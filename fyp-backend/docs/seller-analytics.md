# 商家分析后台设计与实施记录

## 范围

在现有 Medusa 后台新增 `/app/analytics` 页面，服务商家与平台管理员。仅新增后台 React 界面及其测试，不改业务 API、权限、数据库、模型或真实环境文件。经复审与验证后提交到功能分支，不直接推送 `development` 或 `main`。选择复用后台会话和 Medusa UI，而不是在顾客商城另建商家登录系统；直接展示既有统计，不在浏览器下载订单重算。

## 数据与口径

- 调用 `GET /admin/analytics/sales` 和 `GET /admin/analytics/custom-orders`，只发 GET，携带同源登录会话，禁用缓存。店铺隔离由现有服务端权限决定；不提供任意店铺 ID 输入框。
- 日期筛选按 UTC 自然日，支持近 7/30/90 天与自定义，最多 366 天。默认人民币，可切换美元、新加坡元、欧元，币种分开查询、不混合汇总。
- 普通订单：显示净收入、产生正净收入的订单数、平均订单金额、每日收入与订单数量，以及接口返回的收入前十商品及其销量。不能把该接口的收入排序称为完整销量榜；完全退款订单不计入该接口订单数。
- 金额按 Medusa v2 主单位直接格式化，不擅自除以 100；现有销售聚合逻辑直接累加 Medusa 订单/扣款金额，没有单位换算。参考 [Medusa 金额文档](https://docs.medusajs.com/learn/fundamentals/data-models/big-numbers)。后端函数有旧的 minor-unit 注释，前端不据此二次缩放；上线前由 S1 复核实际账本单位。
- 定制订单显示申请量、进行中、交付、取消与各状态数量，不并入普通订单收入。不把付款标记视为收款。
- 评论情感 API 尚未提供，只显示明确的未接入状态，不生成伪情感百分比。

## 界面与失败处理

沿用 Medusa UI、图标和主题，中文默认并提供英文切换。使用可读柱状趋势和明细表，不新增图表依赖。稠密时间段按连续天数分桶、显示各桶日期和合计，原始每日明细仍可查看。筛选后立即清除旧结果；请求可取消，过期响应不得覆盖新筛选。

加载态、无数据、登录过期、无权限、单个接口失败与全失败分别展示；失败不能伪装为零收入。两部分独立展示成功结果，允许重试。截断标记显著提示为部分结果，不能据此显示完整报表。所有可见指标具有明确统计口径，移动端布局和表格在各自容器内适配。

## 实施与验证

1. 先写测试：UTC 日期/范围、主单位金额、请求权限错误、响应契约、缺失日期补零、长区间分桶以及部分失败。
2. 实现界面数据层、双语字典、趋势图和后台路由，复用已存在的类型契约。
3. 跑后端全量 `test:unit`、根目录和后台独立 TypeScript 检查；构建后台验证路由注册。
4. 浏览器使用明确标注的测试响应验证有数据、空数据、截断、401/403/503、筛选竞争和手机布局。实际共享库只读联调另记录，不创建测试业务记录或修改商家角色。
5. 保留 S1 数据单位/商家权限实测、S4 情感接口、S3 中文复核与 S5 性能验收的待办，不将本地样例展示称为全员上线完成。

- 根目录 `tsc --noEmit` 通过；本次新增后台文件的 strict/noUnused 检查通过。
- 全后台的独立严格检查仍报告已有 `src/admin/routes/onboarding/page.tsx:18` 的 `stripeError` 未使用，本轮不修改无关页面。
- `medusa build` 后端与后台前端构建均通过。开发服务器实际注册 `/app/analytics` 与侧栏 Analytics 入口。
- Chrome 在实际 Medusa 后台路由中，使用仅存在于测试浏览器的会话、活动店铺和样例响应，验证中文/英文、币种、近 7/90 天、每日明细、无效日期不发请求、快速筛选不被旧响应覆盖、390px 手机视口无页面横向溢出，以及空结果、部分失败、截断、401/403/503 状态。不存在永久 mock 开关或写入数据库的样例。

## S3 中文本地化复核

- 仪表盘默认使用简体中文，标题、筛选器、指标、趋势图、商品排行、定制申请、加载态、空状态和错误提示均提供中文文案，并保留英文切换用于双语验收。
- 币种选择显示中文名称及国际代码；商品标题属于数据库业务内容，界面不会擅自翻译商家录入的数据。
- 评论情感摘要已准备正面、中性、负面、比例、平均情感得分、平均评分、高频正负面关键词及分析更新时间等中文词条，并提供可直接接收 S4 摘要契约的展示组件。
- S4 当前 Railway 服务尚未部署 `/sentiment`；在 S1/S2 接入情感摘要前，页面明确显示“等待数据接入”，不会生成或伪造情感数据。

## 登录后的人工验收

1. 启动后端，在 `http://localhost:9000/app` 使用现有后台账户登录，再打开 `/app/analytics` 或侧栏“Analytics / 数据分析”。不要使用顾客商城账户代替后台商家账户。
2. 选择实际存在订单的日期和币种，核对净收入、正净收入订单数、客单价与接口原始响应；没有普通已收款订单时显示零值属于正常空数据。
3. 点击每日明细核对 UTC 日期，检查商品收入排行与商品后台链接，确认定制申请与普通收入分开展示。
4. 分别使用获准的商家/管理员账号，确认服务端只返回账号有权访问的数据。不要为测试而手工修改共享库的角色、付款状态或业务订单。
5. 若权限不足，页面会显示无权限提示，不会将错误当作零收入。401 提供重新登录入口，其他接口故障支持重试。
6. 评论情感分析仍等待 S4 API；完整销量排行需要 S1 提供销量排序口径，目前明确展示收入前十，不声称覆盖全部热销商品。
