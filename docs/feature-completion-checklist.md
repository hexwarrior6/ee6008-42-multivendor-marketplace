# 四项后端任务交付核对

更新日期：2026-10-19。以下“已实现”指本地代码与自动化验证，不意味着已推送 GitHub或部署生产。

| 任务 | 已实现内容 | 验收边界 |
| --- | --- | --- |
| 定制产品类别与订单状态机 | 独立、幂等分类初始化脚本；请求→报价→确认→生产→交付；取消分支、状态历史、权限、报价冻结、付款门槛和行锁并发保护 | 分类脚本仅在隔离库运行，未对共享库执行；真实支付/退款验收另计 |
| 设计推荐 API | `GET /store/recommendations`；优先调用 S4 REST `/recommendations`，服务端密钥鉴权、身份透传、格式/有效期/超时校验与规则降级；保留未配置 API 时的旧 JSON 兼容 | 后端部署需配置 API URL 与密钥并发布本次代码；训练由 S4 负责 |
| 与 Medusa 集成 | REST/JSON 模型候选按当前销售渠道与 publishable key 核验；过滤草稿/无变体；当前商品信息回填；身份隔离与禁止共享缓存 | 已部署 S4 服务只读连通；真实个性化效果和 Medusa 线上部署另行验收；详见 S1–S4 REST 对接说明 |
| 分析聚合 API | 普通订单销售净收入；定制申请/状态统计；当前已核验定制扣款快照；店铺隔离、UTC 日期、分页上限与不完整提示 | 定制扣款快照不是完整净收入/结算报表；真实退款财务链路未接通 |

## 本地可核验材料

- 接口与报价确认：[说明](recommendations-and-quote-confirmation.md)。
- S4 JSON 配置、选择策略及跨语言 HTTP 联调：[对接说明](s1-s4-json-integration.md)。
- S4 REST 配置、鉴权及失败降级：[当前对接说明](s1-s4-rest-integration.md)。
- 生命周期与角色权限：[回归指南](s5-custom-order-states-and-regression.md)。
- 定制支付、巡检、收款快照及剩余边界：[支付说明](custom-order-payments.md)。
- 后端：`pnpm test:unit`、`pnpm exec tsc --noEmit`；隔离 HTTP：`pnpm test:feature:http`。
- 最新 REST 验证（2026-10-19）：41 组、399 项后端单元测试，16 项隔离 HTTP 测试及类型检查全部通过，无跳过；包含 HTTP 推荐替身 → Medusa 的鉴权、身份/渠道过滤、异常/空策略/超时降级与恢复。新客户端对实际部署 S4 API 的匿名只读调用成功。临时库已清理，真实 API 密钥未进入源码或文档；部署状态以 GitHub 分支与运行平台记录为准。
- 最终本地验证（2026-10-11 后续修复）：后端 40 组、358 项单元测试，15 个隔离数据库 HTTP 场景，后端类型检查均通过。新增支付关闭/渠道不可用时拒绝创建绑定与规则推荐分页回归；HTTP 包含支付关闭时直接调用准备接口不产生绑定、实际 S4 训练导出 JSON 到推荐 API 的跨语言联调，无跳过。资金相关场景仅用 mock，未访问真实收款/退款服务；真实到账验收仍未进行。提交与发布状态以 GitHub 分支记录为准。
- 前台：`pnpm test:custom-order-payments`、购物车/结账/边界/申请回归和类型检查。
- 共享库只读巡检可由获准管理员执行 `pnpm audit:custom-order-payments`；该命令不修复或删除任何数据。

## 完成上线仍需要的确认

1. 2026-10-10 已确认生产前单笔足额微信付款的全额退款实现范围；管理员接口已接入。仅模拟测试、真实退款默认关闭，不包含真实资金执行授权，部分退款与生产后退款未实现。
2. 获准的商户测试环境、完整参数、可达 HTTPS 回调以及真实付款/退款的专门验收授权。
3. 组长确认共享环境分类初始化及发布安排；GitHub 提交/PR/合并需要另行操作，本轮未推送。

不得以模拟支付、单元回执样本或管理员手工付款标记代替真实资金验收，也不得将上述待确认项标为已完成。
